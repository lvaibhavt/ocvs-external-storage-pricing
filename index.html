    How the figures work

    • One datastore = one volume. The tool assumes each datastore is a single volume (or file system) of the size you enter, grown in whole TiB — the normal way OCVS datastores are built. Only if the size is larger than one volume can be (32 TiB for OCI Block Volume) does it use more.
    • Expected IOPS and throughput come from the provider's published rate for that performance level, up to the maximum per volume. Example: OCI Balanced gives 60 IOPS per GB with a maximum of 25,000 IOPS per volume, so a 20 TiB datastore gets 25,000 IOPS and 480 MB/s — the same figures the OCI cost estimator shows.
    • Prices are monthly list prices. 1 TiB = 1,024 GB/GiB, as in each provider's calculator. Hours per month (default 730) only affects the services billed per hour.

    For a deeper look at OCI storage performance with OCVS, see Oracle's articles: Performance of OCI Block Volume with OCVS standard shapes · How OCI set new storage performance standards

    Before quoting these figures

    • Indicative only. Public list prices without discounts. Confirm on the provider's own calculator before sharing with a customer.
    • Not in the price: FSx throughput capacity, ANF Flexible throughput, Filestore custom performance and OCI High Performance Mount Targets are charged separately.
    • Storage only: no VMware nodes, networking, egress, backup, support or taxes.
